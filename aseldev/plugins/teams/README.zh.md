# 持久化团队

[English](README.md) | 中文

这是一个按需启用的 AselDev 插件，用于由协调者管理专长 agent（智能体）。宿主代码、浏览器代码与调度逻辑都位于此目录；无需修改 Harness 核心或自带预设。

## 安装

在检出目录中运行 `powershell -NoProfile -ExecutionPolicy Bypass -File aseldev/setup-profile.ps1`。此命令构建客户端，将 `@aseldev/dsh-teams` 链接到配置方案的插件搜索目录，并在 AselDev 配置方案补丁中添加对应条目。安装后刷新现有 Harness 页面。如果当前进程无法发现新的客户端包，请通过常规 AselDev 启动器重启，不要另开一个服务器。更新宿主实现代码后也应重启该启动器；仅刷新浏览器并不会更新宿主代码。

配置方案补丁与团队数据存储在 `$DSH_HOME` 下（AselDev 启动器使用 `~/.dsh-aseldev`）。请备份此目录。上游源码更新不会替换保存的团队数据。上游插件 API 变化仍可能要求适配此插件；拉取更新前，请提交或另行备份 AselDev 源码。

如需停用功能但保留数据，请在配置方案补丁生成的 AselDev 区块之后添加 `id: aseldev-teams` / `disabled: true` 覆盖项。重新启用后保留专长定义与历史；中断的任务仍需显式恢复。

## 使用

1. 打开普通的协调者会话，然后打开侧栏中的 **Team**。该会话就是**项目经理（PM）**：它负责规划、通过 `team_manage` 委派任务、审阅工作 agent 报告并回复用户，而不亲自实现任务。
2. 首次加载时会预置成员：**高级后端开发**（写入）、**高级前端开发**（写入）和**高级 QA**（只读）；原先的 Researcher、Builder、Reviewer 会被替换。可在 Team 面板中添加或编辑专长定义。
3. 每个角色自带默认技能（`aseldev/skills/roles/<角色>/SKILL.md`），技能内容就是该角色的指令，因此常规任务无需再写角色说明。**PM 技能**（`aseldev/skills/roles/pm/SKILL.md`）定义协调者的规划与委派循环。**设置 → 团队**页面可编辑所有角色技能、Ponytail 等级与自动续跑轮数；保存后对下一次任务生效。
4. 分配任务标题、完整提示词、可选依赖，以及工作区相对文件或目录的保留范围。写入任务必须声明保留范围；`.` 表示整个工作区。目录保留包括后代路径；不接受通配符或父目录遍历。未指定设计方向的 UI 任务会要求前端 worker 先询问 PM，由 PM 指定已安装的 taste 技能（`design-taste-frontend`、`high-end-visual-design`、`gpt-taste` 等，见 `aseldev/skills/`）。
5. 设置团队并发上限。协调者在线时，符合条件的独立任务即可启动。协调者也能通过 `team_manage` 分配任务。
6. Team 面板是只显示状态的**环形轨道**：每个角色在 PM 核心周围有一个节点，可一眼看到进行中 / 排队 / 完成 / 受阻 / 空闲，并显示实时摘要与自动刷新时间。有工作会话的角色节点可点击打开该会话；团队暂停时显示恢复按钮。分配、重试、取消和后续消息都通过 PM 对话（`team_manage`）进行，而不是面板。

写入型工作 agent 按配置的 Ponytail 等级（`lite` | `full` | `ultra`，默认 `full`，来自设置 → 团队）工作；PM 会在每次写入任务中传递该等级。PM 会自动持续执行，并在达到自动续跑预算（或目标完成、被阻塞）时停止并汇报进度。

编辑专长定义仅影响未来分配的任务，不改变现有工作 agent。工作 agent 继承协调者的工作区与模型路由。指令和模式会随任务保存快照；指令通过已记录的任务消息传给模型，而不是经过插值的人设模板。工具策略会阻止递归委派与团队管理。

## 设置 → 团队

**设置 → 团队**区域列出项目经理技能与每个角色技能的可编辑文本区，支持逐角色保存、Ponytail 等级选择以及自动续跑轮数。它通过与本插件 Team 面板相同的回环信任 API 读写。保存角色技能时也会同步存储中的角色文本，使面板与看板显示 worker 实际收到的内容。设置保存在 Harness 设置存储中；角色技能位于 `rolesDir` 目录（默认：本检出的 `aseldev/skills/roles`）。

## 侧边栏入口

除非配置条目设置 `showLauncher: false`，否则浏览器端会注册一个 `sidebar.launcher` 入口。关闭时其他行为一律不变：宿主引擎、工具、所有任务分配以及设置 → 团队区域都保持原样，面板本身的注册也没有改动，只是不再注册它的侧边栏按钮。插件行配置不会传到浏览器，因此浏览器端在注册前会向宿主读取一次 `GET /aseldev-teams/api/launcher`（`{ "showLauncher": boolean }`）：回答 `false` 时不注册，回答 `true` 时注册；请求失败或路由不存在时仍然注册，避免宿主异常静默隐藏面板。

`aseldev/setup-profile.ps1` 在本配置方案中写入 `showLauncher: false`，因为等距办公室会注册自己的 `sidebar.launcher` 入口；该配置方案默认由办公室取代 Team 入口。设为 `showLauncher: true` 可同时显示两个按钮，或移除办公室条目只保留本入口。

## 调度与持久性

每个协调者会话拥有独立的任务历史与并发设置。专长定义在协调者会话之间共享。团队元数据以原子方式写入 Harness 主目录的 `teams/state.json`；工作 agent 的 transcript（文本记录）使用现有会话持久化机制。

任务从 queued 转为 starting、working，最终进入 done、failed、canceled 或 blocked。取消中的任务会保留并发名额和文件保留范围，直到收到真实的工作 agent 终止事件。依赖失败会阻塞下游任务，直到显式重试。降低并发上限不会取消已经运行的工作 agent。

每个团队的默认并发数为三。插件范围的总上限默认为十二，适用于所有团队。二者都可通过宿主插件配置字段 `maxActive` 和 `maxLimit` 设置；`dir` 指定团队数据目录。请仅在任务确有需要时提高总上限。

进程或插件重启后，团队处于暂停状态，执行中断的任务标为 blocked。重试前请检查共享文件，再显式恢复排队任务。已接受但未记入日志的工作 agent 收件箱消息不具备持久性；插件不会静默重放它们。若已存在工作 agent 会话，重试或直接后续消息会复用该会话。

显示的结果是工作 agent 整个激活周期的最终文本，并不保证对应某一条收件箱消息的独立结果。停止请求表示请求取消，而非立即终止。

## 宿主配置

在配置方案的 `aseldev-teams` 条目中设置宿主字段。请将用户覆盖项保留在安装脚本生成的区块之外。

| 字段 | 用途 |
|---|---|
| `dir` | 数据目录；默认为 `$DSH_HOME/teams`。 |
| `maxActive`、`maxLimit` | 团队默认并发数与插件范围的总上限。现有团队保留各自设置；降低总上限之前，请先调低超过新上限的已保存团队并发数。 |
| `provider` | 已注册的可继续 subagent provider；默认为 `spawn`。 |
| `model` | 可选的工作 agent 全局 `provider`、`model` 和 `maxTokens` 覆盖。未设置时，创建工作 agent 会继承协调者路由。 |
| `personaMode` | `append` 使用团队人设；`inherit` 保留预设人设。这不是按专长保存的独立预设。 |
| `readTools` | 只读专长 agent 的显式检查工具允许列表。仅配置你确信不会修改共享文件的工具。 |
| `delegationTools` | 额外禁止写入型工作 agent 使用的工具名称。内置委派限制仍然生效。 |
| `workerDelegation` | `true` 允许**写入型**工作 agent 使用委派工具（`subagent`、`send_message`、`workflow` 等）。默认 `false`。嵌套工作 agent 不受协调者并发与保留范围协调，独占编辑范围不再有保证；团队管理始终仅限协调者。 |
| `interruptWaitMs` | 停止请求的等待预算；默认为 15000 毫秒。停止请求本身并不能证明已经终止。 |
| `rolesDir` | 角色技能目录（`<角色>/SKILL.md`）。默认本检出的 `aseldev/skills/roles`；设置 → 团队会编辑该目录下的文件。 |
| `ponytailLevel` | 写入任务的默认 Ponytail 强度：`lite`、`full` 或 `ultra`。默认为 `full`。 |
| `autoRounds` | 项目经理自用户最后一条消息后自动运行的轮数上限，超过后必须汇报。默认为 8。 |
| `showLauncher` | `false` 时浏览器端不注册 `sidebar.launcher` 入口。默认为 `true`。一个配置条目同时配置两端，因此由宿主校验该字段；参见[侧边栏入口](#侧边栏入口)。 |

## 共享文件协调

保留范围会串行化声明范围重叠的编辑任务，包括读者与写者之间的重叠。路径比较不区分大小写；即使不同团队位于不同工作区，相同相对路径也会被保守地串行化。未声明范围的只读任务会对写者保留整个工作区。

保留范围属于建议性的协作机制，不是文件系统锁或沙箱。它不能防止人工编辑、协调者编辑、不相关 subagent 的操作、工具写出声明范围，或符号链接与路径别名。请保持提示词范围明确并审查改动文件。只读专长 agent 获得受限的检查工具集，而不是 shell 或修改工具。这些策略用于协调可信任的工作 agent；写入型工作 agent 保留 shell 权限，并未被本插件沙箱化。

默认禁止工作 agent 委派。设置 `workerDelegation: true` 后，**写入型**工作 agent 可以启动自己的 subagent；这些嵌套工作 agent 不受协调者并发上限与文件保留范围约束，重叠编辑将无法再被串行化。无论何种配置，团队管理（`team_manage`）始终仅限协调者。

## 模型体验

### 模型看到什么

协调者获得项目经理技能以及一行动态说明（自动续跑预算与 Ponytail 等级）；该行内容仅在设置 → 团队变化时更新。工作 agent 获得简短的团队工作说明，角色技能文本随任务消息传入。工作 agent 完成通知使用现有 subagent 机制。团队工作 agent 不能调用仅限协调者的操作或启动更多委派。

### Token 影响

协调者每次组装提示词都会附加 PM 技能与协调行；角色技能仅出现在使用该角色的任务提示词中。任务提示词、返回的任务状态和现有工作 agent 报告按其内容长度消耗 token。

### KV Cache 影响

在文件与设置不变时，PM 技能、协调行与工具定义保持稳定；只有设置变更会触发重新组织文本。任务状态通过工具结果返回，不会在每次进度变化时重写系统提示词。

## 已知限制与后续工作

- 工作 agent 使用协调者的预设和模型路由；不支持按专长定义指定预设或覆盖模型。
- 角色技能是任务开始时读取的文件；存储中的角色文本是回退来源，设置 → 团队的保存会同步二者。直接手改技能文件会在下一次任务生效，但面板文本需经设置保存后才更新。
- 可编辑保存的专长定义，但不提供删除或裁剪任务历史的功能。JSON 存储会随使用量增长，面向小型本地团队，而非大型任务队列。
- 恢复排队任务前请打开协调者会话。调度器不会静默重建离线协调者。
- 本地 HTTP API 仅接受具有同源自定义请求头的回环调用者。不支持远程或局域网团队管理。
- 不提供跨进程协调、持久收件箱、自动崩溃恢复、文件系统锁或递归工作 agent 团队。
- Ponytail 从 [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail)（MIT）移植为 `aseldev/skills/ponytail*`；设计 taste 技能也位于 `aseldev/skills/`。

## 检查

安装常规 Harness 依赖与库产物后，运行 `npm --prefix aseldev/plugins/teams test`，构建两端、严格检查源码类型，并运行客户端、调度器、宿主、Loader 组合及隔离安装测试。安装测试不会修改当前配置方案。针对现有 GUI 运行 `node aseldev/plugins/teams/browser-smoke.mjs --fixtures`，验证已挂载面板及其控件，而不改变已保存的用户数据。所有测试都不会启动替代 GUI 服务器。
