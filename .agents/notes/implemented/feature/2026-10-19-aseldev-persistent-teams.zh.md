# Agent Note: 通过外部插件实现持久化专长团队

Status: implemented

[English](2026-10-19-aseldev-persistent-teams.md) | 中文

## 问题

用户需要可重用的专长 agent（智能体）、协调者会话、共享文件及可见任务状态，同时不想维护 agent loop（智能体循环）的分支。临时运行时包无法跨进程重启保留；修改上游组合 manifest（元数据清单）则增加拉取官方更新时的合并工作。

## 决策

[AselDev 团队插件](../../../../aseldev/plugins/teams/README.md) 位于上游包目录之外，通过用户配置方案补丁加载。本地包链接使现有客户端模块 registry 能够发现其浏览器声明。团队数据存储在 Harness 主目录，与检出目录无关。

保存的专长成员是定义；工作 agent 是可继续对话的子会话。每个协调者会话拥有自己的任务分配和并发设置。插件使用现有的[可继续 subagent 生命周期](2026-07-28-continuable-subagent-conversations.md)，不再实现第二个 agent 驱动器、transcript（文本记录）格式或消息投递权限。它不扩大父到子的权限，也不改变现有的[当前轮次中断](2026-08-06-continuable-subagent-interrupt.md)操作。

任务队列在消息进入收件箱前调度任务。一个任务覆盖工作 agent 的完整激活周期，因此释放并发名额和声明文件保留范围的是 subagent 终止事件，而不是推测的单条消息完成。分配任务时保存专长定义快照，避免后来编辑成员定义影响执行中的任务。后续消息使用同一个调度器并保留原工作会话。

文件保留范围协调声明路径，而不阻止写入。目录前缀比较不区分大小写，并保守地串行化重叠范围。读写重叠也会串行化，因为在其他工作 agent 重写文件时进行审查，并不是独立工作。未声明范围的只读任务会对写者保留整个工作区。协调者、人工编辑、不相关 agent 及路径别名均不属于此协调机制。

JSON 存储以原子方式替换。重启会暂停团队并将中断的任务标为 blocked，而不是重放：已接受的收件箱消息未必写入日志，也无法仅凭任务状态安全地推断共享文件写入是否部分完成。

## 考虑过的替代方案

**修改循环与自带预设。** 现有的 subagent、工具、提示词、HTTP、配置方案和浏览器 slot API 已提供所需操作。修改核心会引入上游合并冲突，却没有补足任何缺失能力。

**使用临时运行时插件。** 它们适合探测，但会在进程重启时消失，也不能提供永久安装的团队定义。

**使用一次性工作 agent。** 显式结果 Promise 便于收集结果，但不能满足复用工作会话与冷恢复后续消息的要求。

**将保留范围当作文件系统锁。** 共享 shell、符号链接、人工编辑和不相关 agent 都能绕过路径声明。把建议性协作描述成写入隔离，会承诺插件并未实施的保证。

**自动恢复所有排队和运行中的任务。** 重启可能丢失已接受的收件箱内容，却保留部分文件改动。显式恢复把重放权限留给用户或协调者。

## 影响

此功能不修改上游核心或自带预设。官方更新保留用户数据，但插件 API 变化仍可能要求本地适配。AselDev 插件与安装脚本需要各自已提交的备份。

工作 agent 继承协调者的预设、工作区和模型路由。不提供按专长选择模型、独立预设、远程管理、跨进程调度、持久收件箱或自动崩溃恢复。团队输出覆盖整个激活周期，而不是归因于单条消息的独立结果。取消会保留范围，直到工作 agent 终止。

## 验证

[调度器测试](../../../../aseldev/plugins/teams/engine.test.mjs)覆盖持久性、中断后重启、依赖失败、直接后续消息、发布与终止竞争、跨团队有界并发、取消、脱离内部引用的查询以及文件保留范围重叠。[Loader 组合测试](../../../../aseldev/plugins/teams/composition.test.mjs)驱动真实的协调者和工作 agent 回合，以无需密钥的记录固定已记录的输入与输出，并通过销毁前保留的引用检查工具和 HTTP 路由是否移除。[安装测试](../../../../aseldev/plugins/teams/setup.test.mjs)在临时主目录中验证幂等配置，包括过期链接以及拒绝替换真实目录的行为。[浏览器冒烟测试](../../../../aseldev/plugins/teams/browser-smoke.mjs)在现有 GUI 地址上检查已安装的面板，不改变已保存的用户数据。

现有可继续生命周期与中断说明仍各自保留独立的运行时设计依据；此插件使用这些操作，不替代其中任何决策。
